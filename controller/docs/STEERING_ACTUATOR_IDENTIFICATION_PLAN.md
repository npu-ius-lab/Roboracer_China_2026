# TianRacer 无舵角传感器转向执行器辨识方案

## 1. 基线与目标

`stable` 分支和 `stable-20260815-v1` 标签冻结了已经实车验证的
1.5 rad/s、V1 残差 MPCC。所有辨识和模型修改只在
`steering-actuator-identification` 分支进行。

车辆没有前轮转角传感器，因此不能把辨识结果称为舵机轴的真实机械参数。
本项目要辨识的是 MPCC 真正需要的“转向命令到等效前轮转角/车辆横摆响应”
模型。通信、底层控制、连杆、轮胎建立侧向力等无法分离的部分，都必须被模型
或模型不确定度覆盖。

## 2. 可辨识模型

第一候选使用带静态映射、纯延迟、一阶惯性和实际转角速率限制的灰盒模型：

```text
delta_target(t) = sat(f_static(command(t - Td)))
delta_dot       = clip((delta_target - delta) / tau,
                       -rate_right, rate_left)
```

`f_static` 首先拟合为 `K * command + b`。只有独立验证证明线性模型不足时，
才升级为单调分段线性模型；禁止直接使用无约束高阶多项式。

需要辨识的参数：

- 静态增益 `K`、中位偏置 `b`、左右饱和角；
- 纯延迟 `Td`；
- 时间常数 `tau`；
- 左右实际转角速率上限，以及必要时左右不同的 `tau`；
- 参数随车速变化是否显著。

已有两次 0.6 m/s 赛道安全实验给出了相互一致但尚未独立验证的候选：

| 数据 | K | b [rad] | Td [s] | tau [s] | 动态 R2 |
|---|---:|---:|---:|---:|---:|
| actuator_run01 | 1.158 | -0.0125 | 0.075 | 0.085 | 0.980 |
| actuator_run02 | 1.136 | -0.0183 | 0.105 | 0.062 | 0.986 |

它们说明当前 `K=1, b=0, Td=0, tau=0.08` 很可能漏掉约 0.09 s 的纯延迟，
但不能直接把两次结果取平均后部署。

## 3. 分阶段实验

### A. 静态映射

- 速度固定在 0.6 m/s；使用赛道跟踪器维持安全基线；
- 只在低曲率且有足够边界余量的区段叠加转向平台；
- 左右对称覆盖约 `0, +/-0.04, +/-0.07, +/-0.10, +/-0.14 rad`；
- 每个平台保持至少 0.7 s，并在多圈中打乱顺序；
- 使用 `atan(L * yaw_rate / vx)` 和轨迹曲率分别计算两个低速等效转角代理；
- 检查死区、偏置、左右增益和回差，不能只拟合一个总比例。

### B. 动态响应

- 使用闭环赛道基线，不进行无保护的开环直线或圆周实验；
- 分别在 0.6、1.0、1.5 m/s 采集；
- 在安全直道叠加零均值 PRBS/多正弦激励，幅值从 0.03 到 0.07 rad；
- 激励驻留时间覆盖 0.08、0.12、0.20、0.35 s，以分离 `Td` 和 `tau`；
- 左右样本数量、幅值和速度分布必须平衡；
- 当前物理余量低于 0.20 m、1 s 预测余量低于 0.15 m 或定位异常时立即撤销激励，
  回到稳定控制器，而不是继续完成实验段。

### C. 未激励验证

- 使用完全不参与拟合的 bag；
- 先验证 1.5 rad/s 的稳定 MPCC 圈，再验证 2.0 rad/s；
- 在执行器模型通过前不重新测试 3.4 rad/s；
- 每个配置至少保留连续 3 圈，第一圈和停车圈不用于性能评分。

## 4. 必须记录的信号

- 最终送到底盘的 `/tianracer/ackermann_cmd`；
- 带 header 时间戳的实际命令副本；
- `/livox/imu` 的原始横摆角速度和加速度；
- `/localization/vehicle_odom` 的 pose、vx、vy、yaw rate；
- `/tianracer/odom` 轮速反馈；
- MPCC 当前状态、预测轨迹、估计前轮角、残差修正量和残差置信度；
- 控制器模式、PP 接管、速度上限和安全余量。

辨识必须使用消息自身时间戳。ROS 接收时间只用于统计传输延迟，不能与传感器
时间混在同一条拟合时间轴。

## 5. 拟合方法

1. 低速阶段用运动学关系估计隐变量 `delta`，联合多次 bag 鲁棒拟合静态映射。
2. 固定静态映射后，用输出误差法拟合 `Td/tau/rate_limit`，目标同时包含横摆角
   速度、航向角和横向位移，不能只优化单步 yaw-rate RMSE。
3. 使用 0.1、0.2、0.5、1.0 s 多步 rollout loss；0.2--0.5 s 权重最高，
   因为它决定 MPCC 是否过度相信车辆能够及时转回赛道。
4. 按整圈或整次实验划分训练、验证和最终测试，禁止随机打散相邻时间点。
5. 用按圈 bootstrap 给出每个参数的置信区间，并检查不同速度下的参数漂移。
6. 执行器参数冻结后才能重新辨识 `Cf/Cr`；不能同时自由拟合执行器、侧偏刚度
   和横摆惯量，否则参数不可辨识。

## 6. MPCC 集成

- 当前状态观测器使用已辨识的命令 FIFO、`Td` 和 `tau` 传播隐含前轮角，再用
  IMU/运动学伪测量做小增益校正；日志必须输出 innovation 和 confidence。
- 求解器、低延迟状态前推和 PP 安全 rollout 必须引用同一套执行器参数。
- OCP 对未来命令也必须体现延迟。先比较：
  1. FOPDT 的两级平滑延迟状态；
  2. 与 0.05 s OCP 网格匹配的两阶段命令管线。
  选择多步误差更小且 40 Hz 求解仍满足 deadline 的最小模型。
- 更新标称执行器后，旧 V1 残差会重复补偿旧模型误差。先做 residual OFF 的
  shadow rollout 验证，再基于新标称模型重训残差；禁止直接沿用旧残差做最终结论。

## 7. 验收门槛

- `K` 跨验证 run 变化不超过 5%，`b` 变化不超过 0.01 rad；
- `Td` 跨 run 变化不超过 0.03 s，`tau` 相对变化不超过 25%；
- 低速等效转角动态 RMSE 小于 0.02 rad，验证 R2 大于 0.90；
- 未见数据上 0.2 s yaw-rate rollout RMSE 至少比 stable 标称模型降低 30%；
- 0.5 s 横向位置误差 P95 小于 0.08 m；
- 安全性采用单边标准：模型不能持续比实车更早预测出“已经转回赛道”；
- 加入执行器状态后 MPCC P95 求解时间小于 20 ms，最大值小于 25 ms；
- 1.5 rad/s 实车连续 3 圈的横向误差、PP 接管时间和圈速均不劣于 stable，
  才允许提高转向速率上限。

## 8. 实施顺序

1. 把旧辨识工具迁入当前分支，并增加联合拟合、数据分组和置信区间。
2. 用历史 `actuator_run01/run02` 做回归测试，不用于最终独立验收。
3. 增加安全的 track-PRBS 采集脚本和一键录包脚本。
4. 采集一组新的静态映射 bag 和三档动态 bag。
5. 本地完成拟合、交叉验证和 shadow rollout。
6. 实现并仿真比较 FOPDT 延迟模型的两种 OCP 表达。
7. 远端部署候选，先以 stable 速率和 residual OFF/ON shadow 对照验证。

- 已迁移历史分析工具，并实现完整 bag 等权的联合 FOPDT 拟合、留一验证和
  分组 bootstrap；
- 历史 `actuator_run01/run02` 回归得到 `K=1.1450`、`b=-0.0149 rad`、
  `Td=0.095 s`、`tau=0.0684 s`，但留一 RMSE 为 0.0218--0.0226 rad，尚未
  达到 0.02 rad 门槛；
- 已实现 `track_static_060` 与三档安全 PRBS profile；候选激励会通过多执行器
  模型的一秒边界 rollout，且只在安全直道推进激励时钟；
- 离线工作区回归测试已覆盖激励暂停、零均值序列、安全 rollout 和合成数据
  参数恢复。

下一步只需按 `STEERING_ACTUATOR_DATA_COLLECTION.md` 采集四包新数据。采集前
不会把历史候选参数写入 MPCC，也不会修改 stable。

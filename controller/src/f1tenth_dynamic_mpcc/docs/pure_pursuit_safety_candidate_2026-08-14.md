# MPCC Pure Pursuit 安全候选

## 目标

当 MPCC 的最终预测时域接近或越过控制边界时，不再把转角直接归零。
控制器同时生成一条自适应 Pure Pursuit 候选轨迹，仅在候选轨迹自身安全、
且其最小边界余量明显优于 MPCC 时接管。

普通的 acados `status=4` 不会单独触发切换；触发依据是预测轨迹边界余量、
`track_slack`，或明确的近端/远端赛道约束拒绝。这样不会用几何控制器掩盖
与边界无关的求解器错误。

## 仲裁逻辑

1. MPCC 与 Pure Pursuit 都使用 `ego_width=0.24 m`、赛道左右宽度和
   `boundary_margin=0.10 m` 计算整个预测时域的最小余量。
2. MPCC 风险阈值为 `track_slack > 0.04 m`；其最终轨迹越过安全边界也算风险。
3. Pure Pursuit 最小余量至少为 `0.02 m`，并比 MPCC 至少改善 `0.05 m`，
   才能接管。
4. 接管至少保持 `0.50 s`。MPCC 连续 5 帧获得 `0.08 m` 以上余量后退出，
   避免两个控制器逐帧抖动切换。
5. 候选最大速度仍服从 MPCC 当前动态速度上限，配置上限为 `4.0 m/s`。

## 浅度越界恢复

正常候选仍要求整条轨迹安全。若不可改变的第 0 帧已经轻微越过控制走廊，
则改用恢复判定：初始余量不得低于 `-0.12 m`，后续最多再恶化 `0.02 m`，
必须在 `0.60 s` 内重新进入走廊，并以至少 `0.05 m` 余量结束。恢复速度根据
越界深度在 `0.60–1.50 m/s` 之间连续变化，由发布器继续执行加减速斜率限制。

接受的恢复候选按有效求解处理，不增加 MPCC 连续失败次数。深度越界、候选
继续恶化、无法按时回到走廊时仍进入硬停车；硬停车不会自行解锁。

## 可视化与日志

- MPCC 预测：绿色 `/f1tenth_mpcc/prediction` marker，ID 10。
- Pure Pursuit 候选：紫色 marker，ID 11；仅在风险评估或接管期间有轨迹。
- telemetry 新增候选是否激活、两条轨迹最小余量、余量改善、候选速度、
  转角、前视距离和原因码。
- `candidate_reason_code`：0 无风险，1 风险评估，2 正常接管，3 释放，
  4 候选不安全，5 改善不足，6 浅度越界恢复接管。

## 已完成仿真

- Pure Pursuit 独立故障注入闭环：35 s，约 2.90 圈，候选预测越界 0 次，
  物理边界最小余量 0.101 m。
- acados + 延迟补偿 + 候选联合闭环：600 次求解，注入预测越界后接管 1 次，
  保持 10 个 20 Hz 周期后释放；status=4 为 0，控制失败为 0，物理边界最小
  余量 0.213 m。

上述结果是确定性的模型仿真，不替代低速实车验证。首次部署后应先保持急停
可用，并观察候选 marker、`candidate_active` 和两条预测余量。
